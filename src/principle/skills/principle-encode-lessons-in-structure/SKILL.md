# Encode lessons in structure

Turn a verified lesson into a guard when the rule is mechanically decidable.

1. Identify the concrete failure and the invariant that would exclude it. Use existing evidence; repeated wording alone does not prove a code defect.
2. Choose the smallest fitting owner: a domain type, constructor, metadata constraint, lint rule, runtime check or existing script. Show that the failure is rejected and valid behavior still works.
3. Keep one authoritative enforcement point. Remove redundant reminders only where the structural guard actually covers their meaning; retain necessary explanation of intent.
4. When correctness needs judgment, keep focused guidance at its existing owner with a concrete failure and successful example. A noisy classifier is weaker than honest review.

Done: the known failure is structurally harder to repeat, or its judgment-dependent lesson has one clear instruction and review criterion. Broader investigation of recurring mistakes belongs to a separate correction workflow; this principle does not require one.
