# Correct

Make a demonstrated recurring codebase mistake harder to express, within the authorized scope.

1. **Establish recurrence.** Read relevant corrections, changes and failures. Cite at least two independent occurrences of the same concrete mistake and its consequence. Copied/resumed transcripts, a recap of one incident or an unenforced rule alone do not establish recurrence. Separate observed error from suspected cause; insufficient evidence calls for bounded diagnosis, not policy.
2. **Choose the owner.** Keep one complete correction scoped to the affected behavior. Prefer eliminating the invalid path or duplicate state owner, then domain types, an executable check with an actionable error, then behavior tests. Explain briefly why a higher-level guard is unsuitable. Judgment-only lessons belong to `learn`; prose preferences belong to their writing owner. Stale or misactivated skill instructions belong to their canonical skill/evaluation/install owner, not a product architecture rewrite; use `skill-doctor` when available and apply the repository's skill TDD there.
3. **Prove enforcement.** Preserve a real prior bad example. Show the old mechanism accepts or misses it, then show the new guard rejects it. The corrected case and legitimate neighboring behavior must pass the same local/CI check. Preserve meaningful empty, absent or undefined outcomes when the contract requires them. A test that only copies implementation details cannot establish enforcement.
4. **Complete the authorized correction.** Update affected callers and run focused regressions. For existing widespread violations, enforce new violations while naming the remaining migration scope. Keep the executable owner authoritative; any indispensable judgment rule stays small. Do not commit automatically, maintain a standing rule table, impose a blanket exceptions process, or renovate unrelated code.

Report the two evidence locators, chosen guard and scope, old-failure/new-enforcement results, valid-case checks and remaining limitations. If execution is unavailable, distinguish the proposed proof from a verified correction.
