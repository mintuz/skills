# Format Developer Writing

Use these rules when the writing skill points here for a structured artifact.

## Page frame

- Use exactly one H1 containing a title-case, benefit-led title. Aim for 5–8 words and 50–60 characters when the format permits.
- Use H2 for main sections and H3 for subsections. Keep the hierarchy within H1–H3 and preserve its logical order.
- Open with 1–2 short paragraphs that state the goal and payoff. For a tutorial, name what the reader will learn or build.
- Close with 1–3 short paragraphs that consolidate the outcome and give the next action; use a brief list when it scans better.

## Reading rhythm

- Lead each paragraph with its point and keep it to 3–5 sentences or lines.
- Add a descriptive heading roughly every 200–250 words when the subject supports one.
- Use bullets for peer ideas and numbered lists for ordered steps or rankings. Keep list grammar and punctuation parallel.
- Move dense inline enumerations into lists.
- Reserve bold for key terms or actions and italics for light emphasis.

For rendered pages, target a text column near 65 characters wide. Leave source wrapping to the repository's formatter.

## SEO branch

When the request includes search optimization or a primary keyword:

- place the keyword naturally in the title;
- use it once in a relevant H2 and H3 when both levels exist; and
- emphasize it once only when the emphasis helps the reader.

Prefer natural phrasing over an exact placement that distorts the meaning.

**Complete when:** a heading-only read exposes the payoff and sequence; the page has one H1, an ordered H1–H3 hierarchy, parallel lists, and the required opening and close; when the SEO branch fires, every requested keyword placement is present and natural.
